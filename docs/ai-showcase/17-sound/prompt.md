# Task 17 — Sound effects, generated music and a mute toggle

Branch: `feat/sound`. **Not a Junie session**: implemented by another AI coding tool from a plan
written by a planning agent and approved by the user.

## User request (translated from Indonesian)

"Add sound to this game; right now it is less fun without sound, and make the sound mutable:
gunshots, footsteps, copyright-free music if possible, button sounds, and any other sounds that
are needed."

## User decisions

- Every sound is synthesized with the Web Audio API; zero audio files.
- The music is generated by code (original, copyright-free).
- Enemy footsteps are audible even while the enemy is hidden by fog of war, behind one named
  constant (`ENEMY_FOOTSTEPS`) so it can be turned off.

## Prompt summary

Goal: runtime-synthesized sound effects, generative background music and a mute toggle,
following the approved plan.

Hard constraints:

- Do not touch the sim (`web/src/sim/`), `session.ts`, scoring, kiosk logic, touch controls,
  level code or the 3D probe. Hooks only in `gamePage.ts`, `index.html` (button), CSS and new files.
- The sim purity and three.js lazy-loading tests must keep passing. No AudioWorklet, no blob URLs,
  no audio files, no external fetch (CSP `default-src 'self'`).
- Keep the entry chunk growth under about 2 KB gzip; the engine, effects and music load as a lazy
  chunk via `import()` on the first user gesture.
- No commits; project text in English; no local absolute paths.

Plan (module `web/src/audio/`):

- `events.ts` (pure): `track(prev, snapshot) → { next, events }` from cumulative `stats` deltas
  (several sim ticks can run per frame), bot shots from `state.shots`, footsteps by distance
  walked, defuse start/ticks/complete, spike beeps at 1/2/4/8 Hz by time left, outcome events
  (win/lose stinger, death sweep, explosion), countdown beeps (660 Hz for 3-2-1, 990 Hz for go);
  reset when the session object changes.
- `pattern.ts` (pure): `musicNotes(fromStep, toStep, mood)` in D minor over Dm-Bb-Gm-A, 16 steps
  per bar; moods menu (92 BPM), round (120 BPM with an intense layer when the spike is planted or
  under 10 s left) and calm score/replay.
- `settings.ts` (pure): `{ muted, music }`; `?mute`/`?auto` force silence, `?music=0` turns music
  off; persisted in `localStorage` except in kiosk mode.
- `engine.ts`, `sfx.ts`, `music.ts` (lazy): sfx and music buses → master → compressor, one shared
  noise buffer, a voice cap, music scheduled from the frame loop with 300 ms lookahead, 6 dB duck
  for 400 ms on explosions and stingers.
- `index.ts` facade: creates and resumes the `AudioContext` synchronously inside the gesture
  (iOS), retries until it runs; mute and hidden tabs suspend it.
- Hooks in `gamePage.ts`: gesture unlock listeners before the kiosk block, scene changes in
  `show()`, the live round snapshot after each `session.advance`, replay sounds (YOU panel only,
  1×/2×, normal playback only), button clicks via a bubble-phase listener on `#game`, the M key.
- Mute button `#muteToggle`: fixed top-right (top-left is the kiosk operator tap zone), inline
  SVG icon, `aria-pressed` + `aria-label`, drops focus after a pointer click so Space (fire)
  cannot toggle it.

Tests: events (multi-tick frames, outcome order, footstep interval, beep rate, session reset),
pattern, settings, and a source scan (pure modules use no Web Audio/DOM, the sim never imports
audio, the engine is only reachable via `import()`).

Docs: `docs/audio.md`, `CHANGELOG.md`, this prompt.

Done when: `npx tsc --noEmit` is clean, `pnpm test` passes, `pnpm build:public` prints
`verify-dist: OK`, and the entry/engine chunk sizes are reported.
